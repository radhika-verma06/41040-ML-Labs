Hill Climbing

A simple local search algorithm for improving a complete solution step by step.

Today we are looking at Hill Climbing, which is a local search and optimisation algorithm.

The main idea is very simple. We start with one complete solution. We make a small change to that solution to create a nearby solution, which we call a neighbour. Then we compare the two solutions.

If the neighbour is better, we move to it. If it is not better, we stay where we are.

In this lab, our problem is the Travelling Salesman Problem, or TSP, using Romanian cities.

1 · Understand the problem first

This lab uses a Euclidean TSP

Before we talk about Hill Climbing, we need to be very clear about the problem we are solving.

A salesperson starts from a city, in our case we will use Arad. The salesperson must visit every other city exactly once and then return back to Arad.

The goal is to find a route with the smallest total round-trip distance.

This is different from the shortest-path problems we saw earlier. We are not asking, ‘What is the cheapest path from Arad to Bucharest?’ Instead, we are asking, ‘What is a good ordering of all the cities so that the total tour is as short as possible?’

Also, this lab treats the cities as a complete graph. That means every pair of cities is considered directly connected using straight-line Euclidean distance. We are not following the actual Romania road network.

Important: This is optimisation over a complete tour, not shortest-path search over roads.

2 · What is a solution?

One state is the whole route

['Arad', 'Sibiu', 'Fagaras', 'Bucharest', ..., 'Zerind']

In this problem, one candidate solution is a complete ordering of all the cities.

So unlike a shortest-path problem, where a state may be just one city, here one state represents the entire TSP tour.

Every city must appear exactly once in the route. In this notebook, Arad is kept at the first position, and at the end of the tour we return from the last city back to Arad.

For example, if our route starts with Arad, then goes to Sibiu, then Fagaras, then Bucharest, and continues through all the remaining cities, that whole list is one candidate solution.

If a city appears twice, or if a city is missing, then the route is not a valid TSP solution.

Remember: one complete permutation of the cities = one solution.

3 · Cost function

How do we know which route is better?

Hill Climbing needs a way to score a solution. In our problem, the score is the total route distance.

We calculate the Euclidean distance from the first city to the second city, then from the second to the third, and so on.

After we reach the last city, we also add the distance from the last city back to the first city, because TSP requires a complete round trip.

Since our objective is to minimise distance, a smaller cost means a better solution.

def route_distance(route): total = 0 for i in range(len(route) - 1): total += distance_matrix[route[i]][route[i + 1]] total += distance_matrix[route[-1]][route[0]] return total

Lower distance = better route.

4 · Euclidean distance

Where does each city-to-city distance come from?

Each city has coordinates. To calculate the distance between two cities, the notebook uses the standard Euclidean distance formula.

Conceptually, this is just the straight-line distance between two points.

We do not need to focus heavily on the mathematics here. The important point for Hill Climbing is that the distance function gives us a numerical cost for every route.

Once we can assign a cost to a route, Hill Climbing can compare one route with another.

d(A,B) = √((xA − xB)² + (yA − yB)²)

5 · Neighbour

How do we create a nearby solution?

Current:   Arad → Sibiu → Bucharest → Zerind → Iasi
Neighbour: Arad → Zerind → Bucharest → Sibiu → Iasi

Hill Climbing does not create a completely unrelated route every time. Instead, it creates a neighbour, which is a small variation of the current solution.

In this lab, a neighbour is created by selecting two cities and swapping their positions.

For example, in this small route, Sibiu and Zerind have swapped places. Everything else has stayed the same.

This is useful because the route remains valid. We have not added or removed any cities. We have only changed the order in which two cities are visited.

6 · Neighbour code

Read the swap function carefully

def swap_neighbour(route): neighbour = route.copy() i, j = random.sample( range(1, len(neighbour)), 2 ) neighbour[i], neighbour[j] = ( neighbour[j], neighbour[i] ) return neighbour

The first line creates a copy of the current route. We do this because we do not want to destroy our current solution before deciding whether the new one is better.

Next, the code randomly selects two positions from the route.

Notice that the range starts from 1, not 0. Position 0 contains Arad, so starting from 1 keeps Arad fixed as the starting city.

Then the two selected cities are swapped, and the new route is returned as our candidate neighbour.

7 · Core HC rule

This is the heart of Hill Climbing

if neighbour_cost < current_cost: current_solution = neighbour current_cost = neighbour_cost

This small condition contains the main idea of Hill Climbing.

We calculate the cost of our current route and the cost of the neighbour route.

If the neighbour has a smaller cost, then the neighbour is better, so we accept it and make it our new current solution.

If the neighbour has a larger cost, we reject it and keep the current solution.

If the neighbour has exactly the same cost, it is also rejected because the code uses a strict less-than sign.

8 · Very important implementation detail

This lab checks only one random neighbour at a time

There is one very important detail about this particular implementation.

In some textbook versions of Hill Climbing, the algorithm may examine many neighbours and choose the best one. That is not what this notebook does.

Here, each iteration generates only one random swap neighbour.

If that random neighbour is better, we accept it. If it is worse, we reject it and try another random neighbour on the next iteration.

This also means that finding one bad neighbour does not prove that there are no better neighbours. It only means that this particular random swap was not useful.

Do not say: The algorithm checks all neighbours and chooses the best.

10 · Iterations

What happens inside one Hill Climbing run?

for iteration in range(max_iterations): neighbour = neighbour_function(current_solution) neighbour_cost = objective_function(neighbour) if neighbour_cost < current_cost: current_solution = neighbour current_cost = neighbour_cost history.append(current_cost)

Inside one Hill Climbing run, the algorithm repeats the same process many times.

It generates one random neighbour, calculates the neighbour’s cost, and compares it with the current cost.

If the neighbour improves the route, it becomes the new current solution.

Then the current cost is added to the history so that we can later draw a convergence graph.

In the lab implementation, this inner loop can run for up to 1500 iterations.

11 · Random restarts

Why do we start again many times?

Hill Climbing is strongly affected by its starting solution.

If we begin from one random route, the algorithm may improve it and end up in a reasonably good region. But another starting route may lead to a much better region of the search space.

For this reason, the lab uses random restarts.

A restart means we create a completely new random starting route and run Hill Climbing again from there.

After each restart, we compare the final result with the best result we have found so far.

In the lab implementation, we use up to 40 restarts.

12 · Current vs best

These variables mean different things

VariableMeaning
current_solutionThe route Hill Climbing is currently using inside one restart.
current_costThe cost of that current route.
best_solutionThe best final route found across the restarts completed so far.
best_costThe smallest final cost found across those restarts.

The word current means where the algorithm is right now within one restart.

The word best means the best result found across all of the restarts we have completed so far.

The code starts with best_cost = math.inf. This simply means we initially treat the best cost as infinitely large, so the first real route we finish with will automatically be better than infinity.

13 · Local optimum

The biggest weakness of Hill Climbing

Hill Climbing only accepts moves that immediately improve the current solution.

This is simple and efficient, but it creates a problem. Sometimes the algorithm may reach a route where the nearby changes it tries are worse, even though a much better route exists somewhere else.

We call this being stuck in a local optimum or a locally good region.

For example, imagine our current route has a cost of 1800. There might be a route with cost 1600 somewhere else, but perhaps reaching that region requires temporarily moving from 1800 to 1840 first.

Hill Climbing will not accept the 1840 move because it is worse than 1800. Therefore it may never reach the 1600 route through that path.

1800 → 1840 → 1600
HC refuses the middle step, even though the final result would be better.

14 · Convergence graph

How should we read the graph?

3500, 3500, 3310, 3310, 3310, 3040, 2900, 2900, ...

The convergence graph shows how the current accepted cost changes over the iterations.

When the line goes down, it means the algorithm found a better neighbour and accepted it.

When the line is flat, it means the algorithm tried one or more neighbours that were not better, so it stayed at the same current solution.

For this version of Hill Climbing, the line should not go upward, because the algorithm never accepts a worse route.

So the general pattern we expect is a staircase that moves downward and then becomes flatter as improvements become harder to find.

15 · Termination

When does this implementation stop?

Another important detail is the termination condition.

This implementation does not stop immediately when it sees one worse neighbour. It simply rejects that neighbour and continues.

The inner Hill Climbing loop stops when it reaches the specified maximum number of iterations.

Then, if random restarts are being used, the algorithm starts again from another random route.

After all restarts are finished, the algorithm returns the best route and best cost it found.

One rejected neighbour does not terminate the algorithm.

16 · Full algorithm story

Now read the whole function as a process

best_solution = None best_cost = math.inf for restart in range(restarts): current_solution = random_solution_function() current_cost = objective_function(current_solution) for iteration in range(max_iterations): neighbour = neighbour_function(current_solution) neighbour_cost = objective_function(neighbour) if neighbour_cost < current_cost: current_solution = neighbour current_cost = neighbour_cost history.append(current_cost) if current_cost < best_cost: best_solution = current_solution best_cost = current_cost

We begin with no best solution and an infinitely large best cost.

For each restart, we generate a new random route and calculate its cost.

Then, for many iterations, we generate one random neighbour and compare its cost with the current cost.

If the neighbour is better, we move to it. Otherwise, we keep the current route.

At the end of that restart, if the final current cost is better than our best cost so far, we save it as the new global best result.

Finally, after all restarts, we return the best route and cost we found.

17 · Connect to UCS

Why this feels different from Lab 1

Main goalReach a goal node through a low-cost path.Improve a complete TSP tour.

Main structurePriority queue / frontier.Current solution and one candidate neighbour.
DecisionExpand the lowest accumulated path cost.Move only if the neighbour lowers total route cost.

If you are comparing this with Uniform Cost Search, the key difference is that UCS systematically explores paths toward a goal.

Hill Climbing is different. It starts with one complete candidate solution and repeatedly modifies that complete solution locally.

There is no priority queue and no frontier of paths. We mainly keep the current route, generate a neighbour, compare costs, and decide whether to move.

18 · Transition to Simulated Annealing

Why does SA behave differently?

Hill Climbing

Worse move?

Never accept it.

Simulated Annealing

Worse move?

Sometimes accept it.

This limitation of Hill Climbing gives us a natural reason to study Simulated Annealing.

Hill Climbing never accepts a worse move. Simulated Annealing can sometimes accept a worse move, especially when the temperature is high.

That may sound strange, but it can help the algorithm escape a locally good region and move toward a better region later.

So one useful way to remember the difference is: Hill Climbing is strict and greedy, while Simulated Annealing allows some controlled exploration.

20 · Final summary

If you remember one explanation, remember this

A solution is one complete valid ordering of all the cities. We calculate its total Euclidean round-trip distance, and because this is a minimisation problem, a smaller distance means a better solution.

Hill Climbing creates a neighbour by swapping two cities in the current route. It calculates the neighbour’s cost and compares it with the current cost.

If the neighbour is better, Hill Climbing moves to it. If it is equal or worse, Hill Climbing keeps the current route and tries another random neighbour on the next iteration.

Because worse solutions are never accepted, the convergence curve can move downward or stay flat, but it should not rise.

This greedy behaviour can cause Hill Climbing to get stuck in locally good regions, so the lab uses random restarts to try several different starting routes and keep the best result found.

That is the core Hill Climbing story for this lab.
