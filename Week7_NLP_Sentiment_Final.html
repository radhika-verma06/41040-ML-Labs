1. Tokenisation

Computers do not begin with an understanding of a sentence. Tokenisation breaks text into smaller units so later NLP steps can work with them.

CORE
A

Sentence tokenisation

Splits a paragraph into sentence units. In the notebook this is done with sent_tokenize().

sent_tokenize_result = sent_tokenize(EXAMPLE_TEXT)

Punctuation such as a full stop is not always enough by itself. A tokenizer uses language rules, so abbreviations such as “Mr.” do not automatically end a sentence.

CORE
B

Word tokenisation

Splits text into word-level pieces. In the supplied example, punctuation also appears as separate tokens.

word_tokenize_result = word_tokenize(EXAMPLE_TEXT)

The notebook output includes pieces such as Mr., ,, ? and splits “shouldn't” into should and n't.

Visual: one sentence becomes tokens

Themoviewasnotgood.

Think of tokenisation as putting boundaries around useful pieces. The model still does not understand meaning yet. It simply has consistent units it can process.

Themoviewasnotgood.

After optional filtering: common words and punctuation may be removed, but “not” is important for sentiment because it changes the meaning of “good”.

Why this matters: a later model needs repeatable units. Once text is tokenised, tokens can be counted, filtered, grouped into n-grams or mapped to vectors.

Stop words and punctuation

Stop words

Very common words such as “the”, “and”, “is”, “you” and “are”. Depending on the task, removing them can reduce noise.

Punctuation

for w in word_tokenize_result:

2. N-grams

An n-gram is a consecutive sequence of N items. Here the items are words.

Unigram

N = 1

very good movie

Bigram

N = 2

very good good movie

Trigram

N = 3

very good movie

Visual: a sliding window

For a bigram, imagine a window that always holds two neighbouring words and slides one step at a time.

this movie movie was was not not very very good
Why it helps: “good” alone sounds positive. “not good” captures a short phrase whose meaning is negative. N-grams preserve that local relationship.
Key idea: single words give vocabulary information; n-grams preserve a small amount of local order. “not good” is more informative than counting “not” and “good” independently.

3. Word2Vec and word embeddings

Instead of representing a word only as a label or count, an embedding represents it as a dense vector of numbers. The individual dimensions are not meant to be read one-by-one; relationships in the vector space are the useful part.

CORE

Vector representation

The notebook loads a supplied model from text_data/words.txt and accesses vectors such as words["city"] and words["book"].

A vector is simply a list of numeric coordinates that places a word somewhere in a high-dimensional space.

CORE

Meaning through geometry

Words used in similar contexts tend to end up closer together. The notebook finds nearby words for “book”, including “books”, “essay”, “memoir”, “novella” and “anthology”.

Think of Word2Vec as a meaning map

The picture below is only a 2D sketch. Real Word2Vec vectors have many dimensions.

writing / booksplaces
What distance means: words appearing in similar contexts tend to have vectors that are closer together. The useful information is the relationship between vectors, not the meaning of one individual coordinate.

The analogy in the notebook

vector(Paris) − vector(France) + vector(England) ≈ vector(London)
words_relationship = words["paris"] - words["france"]
result = words_relationship + words["england"]
vectors.closest_word(result)   # 'london'
Interpretation: the operation is not “doing geography” directly. It is using a pattern encoded in the learned vector space. A similar relation from France→Paris is transferred to England→?.

4. TF-IDF

TF-IDF gives a larger weight to terms that are important in a document but not common across the whole collection.

TF — Term Frequency

How often term t appears in document d.

TF(t,d) = count of t in d

DF / IDF

DF is how many documents contain the term. IDF gives more weight to terms found in fewer documents.

IDF(t) = log(N / DF(t))

TF-IDF

Combine local frequency with corpus-level rarity.

TF-IDF = TF × IDF
Intuition: a word that appears often in one document can be useful, but if it appears in almost every document it is less distinctive. TF-IDF balances those two facts.

“cinematography was stunning”Each important term may appear onceIf “cinematography” is rare in the corpus, IDF is higherIt can still receive a useful weight

“movie” appears across many documents, so it is less distinctive. “cinematography” appears in fewer documents, so its IDF component is larger.

Easy rule: TF asks “Is this word frequent in this document?” IDF asks “Is this word rare across the whole collection?” TF-IDF is high when both conditions make the word informative.

What the NLP notebook does

vectorizer = TfidfVectorizer()
tfidf_matrix = vectorizer.fit_transform(all_documents)

similarity_scores = cosine_similarity(
    tfidf_matrix[-1],      # query
    tfidf_matrix[:-1]      # corpus documents
)

The notebook converts a small corpus plus a query into a TF-IDF matrix and then compares the query with the corpus using cosine similarity.

Note on exact numbers: the slide gives the core hand-calculation idea. TfidfVectorizer also applies implementation defaults such as normalisation, so the numerical vectors need not look like a simple raw TF × IDF hand calculation.

6. Four classical classifiers

The implementation differs, but the surrounding pipeline is almost the same. The main comparison is how each model makes its decision from the text features.

QUICK BRIEF

Naive Bayes

Idea: estimates which class is more probable from the words present in the text.

It combines evidence from features using Bayes' rule and makes a simplifying “naive” conditional-independence assumption.

feats = {t: True for t in tokens if t}
classifier = NaiveBayesClassifier.train(train_docs)

The saved notebook run uses this option and reports accuracy 0.6000 on a five-example test set.

QUICK BRIEF

Logistic Regression

Idea: learns a weighted combination of TF-IDF features and converts the score into a probability for the positive class.

Pipeline([
  ("tfidf", TfidfVectorizer(ngram_range=(1,2))),
  ("lr", LogisticRegression(max_iter=1000,
                             solver="liblinear"))
])

Positive-weighted features push the decision one way; negative-weighted features push it the other.

QUICK BRIEF

Linear SVM

Idea: finds a separating boundary between the two classes with a large margin.

Pipeline([
  ("tfidf", TfidfVectorizer(ngram_range=(1,2))),
  ("svm", LinearSVC(random_state=42))
])

The notebook reports the magnitude of the decision score as a margin-style confidence proxy.

QUICK BRIEF

Decision Tree

Idea: learns a sequence of feature-based splits until it reaches a class decision.

DecisionTreeClassifier(
  criterion="gini",
  max_depth=50,
  min_samples_leaf=2,
  random_state=42
)

Trees are easy to interpret conceptually, but on sparse high-dimensional text features they can behave very differently from linear models.

What do the TF-IDF parameters mean?

ngram_range=(1,2): include single words and two-word sequences.

min_df=1: keep a feature even if it appears in only one training document.

strip_accents="unicode": normalise accented characters using Unicode processing.

Why use a Pipeline?

The pipeline keeps feature extraction and the classifier together. During fit(), TF-IDF is learned from the training text and the resulting vectors are passed to the classifier. During predict(), new text goes through the same transformation before classification.

1. Data

IMDB dataset: 25,000 training reviews and 25,000 test reviews. The notebook keeps the top 20,000 word IDs.

2. Padding

Reviews have different lengths, so pad_sequences(..., maxlen=500) makes every sequence length 500 by truncating or padding.

3. Training

The model uses AdamW, binary cross-entropy, 9 epochs and a 20% validation split. The fit() call explicitly uses batch size 128.

4. Evaluation

The saved notebook output reports test accuracy of approximately 0.8536.

model = Sequential()
model.add(Embedding(max_features, 32))
model.add(LSTM(32))
model.add(Dense(1, activation='sigmoid'))

model.compile(
    optimizer='adamW',
    loss='binary_crossentropy',
    metrics=['acc']
)

history = model.fit(
    input_train, y_train,
    epochs=9,
    batch_size=128,
    validation_split=0.2
)
Why sigmoid? The final output is one value between 0 and 1. The notebook uses a threshold of 0.5: above 0.5 → positive, otherwise negative.
What the saved training history suggests: training accuracy keeps rising to about 0.986, while validation accuracy peaks earlier and validation loss later increases. That divergence is a classic sign that continued training is fitting the training data more strongly than the validation data.
Two useful notebook code checks

Batch size: an earlier variable is declared as batch_size = 32, but the later model.fit() call explicitly passes batch_size=128. The explicit value is the one actually used in training.

Actual label in the final prediction loop: the loop predicts from input_test[i] but looks up the displayed actual label from y_train[i]. If the intention is to compare against the matching test label, the corresponding array would be y_test.
