What is being learned?

The central question: if an agent can move through this world many times, how can it learn which locations and actions are good before it reaches the final reward?
The environment

Markov Decision Process

An MDP is a mathematical description of a decision problem. It defines where the agent can be, what it can do, what may happen next and what reward it receives.

State

The agent’s current situation. In GridWorld, a state is one accessible cell, represented in code as (x, y).

Action

A choice available to the agent: north, south, east or west.

Reward

Immediate feedback received in a state: +1, −1 or the ordinary step reward −0.05.

Transition model

The probabilities of reaching each next state after choosing an action.

Policy π(s)

A rule that tells the agent which action to take in every state.

Discount γ

How strongly future rewards matter. Here γ = 0.95, so future rewards matter, but slightly less than immediate rewards.

Markov property: the next outcome depends on the current state and action. The complete route used to arrive at the state does not need to be stored in the state description.

Long-term value

Reward, return, utility and Q-value

These words refer to different parts of the same decision process. Keeping them separate makes every algorithm easier to understand.

TermMeaningExample question
Reward RImmediate feedback received now.What did I receive in this cell?
Return GThe discounted total of rewards from one point until the episode ends.What total reward followed this visit?
Utility U(s)The expected long-term value of being in state s.How good is this location under a policy or optimal behaviour?
Q-value Q(s,a)The expected long-term value of taking action a in state s.How good is moving east from this location?

Discounted return

Gt = Rt + γRt+1 + γ²Rt+2 + …

With γ = 0.95, a reward received one step later counts as 95% of its value now. A reward received two steps later is multiplied by 0.95². This prefers earlier rewards while still considering the future.

Example: if the remaining rewards are −0.05, −0.05 and +1, the return is −0.05 + 0.95(−0.05) + 0.95²(+1) = 0.805.

Policy

A policy is a map from states to actions. A passive agent is given a fixed policy and learns how good its states are while following it. An active agent must learn which actions to choose.

Planning references

Value Iteration and Policy Iteration

VI and PI are planning algorithms, not the four experience-based agents. They know the reward and transition model and calculate reference utilities before the RL estimates are compared.

VI

Value Iteration

Value Iteration starts with rough utility values, considers every possible action in each state, and repeatedly keeps the action with the highest expected long-term value.

Unew(s) = maxa Σs′ P(s′|s,a)[R(s) + γU(s′)]
Copy the current utilities.
For each state, calculate the expected value of every action.
Store the largest action value as the state’s new utility.
Repeat until the utilities barely change.
PI

Policy Iteration

Policy Iteration begins with a policy, evaluates how good that policy is, and then improves any action that has a better alternative.

Two learning situations

Passive and active reinforcement learning

PASSIVE RL

The policy is already given

The agent follows the fixed policy π. Its job is to learn the utilities of the states experienced under that policy.

In this lab: DUE, TD and ADP.

They answer: “How good are the states when I follow this policy?”

ACTIVE RL

The agent chooses and improves actions

The agent is not restricted to one fixed policy. It explores actions and learns which action is best in each state.

In this lab: Q-learning.

It answers: “Which action should I take here?”

Most important distinction: passive methods learn U(s) while following a supplied policy. Q-learning learns Q(s,a), compares actions and creates behaviour from those learned action values.
Passive RL 1

Direct Utility Estimation

DUE waits until an episode finishes, calculates the return observed after each state visit, and averages the returns for each state.

Follow the fixed policy until a terminal state is reached.
Store the visited states and received rewards.
Work backwards to calculate a discounted return G for every visit.
Update each state utility using the average of its observed returns.
U(s) ← U(s) + [G − U(s)] / N(s)
Example: state A previously had U(A)=0.40 from 4 visits. A new return is 0.60. The new value is 0.40 + (0.60−0.40)/5 = 0.44.
The key DUE update
# Work backwards through the completed episode
G = reward[t] + gamma * G
N[state] += 1
U[state] += (G - U[state]) / N[state]

Strength: the idea is simple and it uses the full outcome of an episode. Limitation: it must wait until the episode ends, and early estimates can vary greatly because complete returns are noisy.

Passive RL 2

Temporal Difference learning

TD updates after each transition. It does not wait for the terminal state. It uses the immediate reward and the current estimate of the next state.

U(s) ← U(s) + α [r + γU(s′) − U(s)]

The bracket is the TD error. It compares the old estimate U(s) with a one-step target: reward now plus the discounted estimate of the next state.

Example: U(s)=0.30, reward r=−0.05, U(s′)=0.50, γ=0.95 and α=0.20.
Target = −0.05 + 0.95(0.50) = 0.425.
TD error = 0.425−0.30 = 0.125.
New U(s) = 0.30 + 0.20(0.125) = 0.325.
The key TD update
Ns[s] += 1
U[s] += alpha(Ns[s]) * (
    reward + gamma * U[next_state] - U[s]
)

Strength: it learns online, one step at a time, without knowing transition probabilities. Limitation: its target contains another estimate, so learning depends on the learning rate and may take many updates to settle.

Passive RL 3

Adaptive Dynamic Programming

ADP learns a model of the environment from experience, then uses that learned model to evaluate the fixed policy.

What is learned?

The reward observed in each visited state and the probability of reaching each next state after a state-action pair.

How is it used?

The estimated rewards and transition probabilities form a learned MDP. Policy evaluation then calculates utilities inside that model.

P(s′|s,a) ≈ count(s,a,s′) / count(s,a)
Example: east was chosen from state A 10 times. The agent arrived at B 7 times, C 2 times and remained in A once. Its learned probabilities are 0.7, 0.2 and 0.1.
The key ADP model update
Nsa[(s, a)] += 1
Ns1_sa[(next_state, s, a)] += 1
P[(s, a)][next_state] = Ns1_sa[(next_state, s, a)] / Nsa[(s, a)]
U = policy_evaluation(pi, U, learned_mdp)

Strength: the learned model explains how the environment behaves and can use planning calculations. Limitation: storing and repeatedly evaluating a model can be expensive when the number of states is large.

Active RL

Q-learning

Q-learning learns a separate value for every state-action pair. It can improve behaviour without being given the transition probabilities or a fixed policy.

Q(s,a) ← Q(s,a) + α[r + γ maxa′Q(s′,a′) − Q(s,a)]

The update asks: “After the reward I just received, what is the best learned action available in the next state?” The max makes the target greedy, even while the agent’s behaviour continues to explore.

Example: Q(s,east)=0.20, reward=−0.05, best next Q=0.60, γ=0.95 and α=0.20.
Target = −0.05 + 0.95(0.60) = 0.52.
New Q = 0.20 + 0.20(0.52−0.20) = 0.264.
The key Q-learning update
best_next = max(Q[(next_state, a1)] for a1 in actions(next_state))
target = reward + gamma * best_next
Q[(state, action)] += alpha(n) * (target - Q[(state, action)])

Exploration in the supplied agent

Ne = 50 is an exploration threshold. Actions tried fewer than 50 times receive the optimistic exploration value Rplus = 2. After enough trials, the learned Q-value is used instead.

Exploration function
def f(u, n):
    return Rplus if n < Ne else u

action = max(actions, key=lambda a: f(Q[(state,a)], Nsa[(state,a)]))

For reporting, the notebook converts action values into a state utility using U(s)=maxₐQ(s,a). The best action in each state also gives the learned policy.

What does convergence mean?

A method converges when its estimates stop changing substantially and settle near stable values. The plots show the estimate at each state across many trials. VI U and PI U are horizontal references. An RL curve approaching those references suggests its experience-based estimate is becoming similar.

A curve reaches the reference quickly: learning is comparatively fast for that state under those settings.
A curve jumps up and down: transitions and returns vary. Look for the overall trend rather than one trial.
A stable curve differs from VI or PI: the passive policy may value the state differently, the state may be visited rarely, or more trials and parameter changes may be needed.
